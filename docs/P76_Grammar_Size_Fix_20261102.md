# P76 grammar 크기 초과 수정 설계

## 확인 원인
2026-11-02 20:05 KST 실행 41433922561의 비공개 오류 증거에서 compiled grammar 크기 초과를 확인했다. 이번 요청의 거부 사유는 잔액 부족이 아니다. 기존 PR17/19/20은 이 스키마 크기 문제를 수정하지 않았다.

## 구현
Notion 정본은 보존하고 API 호출 경계에서 NB-S의 arc만 변환한다. e1..e7의 스키마가 모두 동일하고 알려진 구조와 정확히 일치할 때 7개 객체 정의를 단일 items 정의를 가진 배열로 대체한다. 미래 정본의 서로 다른 회차 스키마나 추가 제약은 자동 삭제하지 않는다. 정본은 deep copy하여 원본을 변경하지 않는다.

API에 minItems=7/maxItems=7을 보내지 않는다. 현재 공식 제한에서 배열 길이는 API에 강제할 수 없으므로 시스템 지시문에 1..7 각각 한 번씩 순서대로 작성하도록 명시하고, 기존 B01 검증에서 정확한 7회차 집합을 확인한다. 누락/중복/초과는 실패로 남겨 기존 총3회 범위의 수정 대상으로 처리하며 완성으로 승인하지 않는다. 배열 자체가 아니거나 회차 번호가 정수가 아니면 invalid_arc_shape로 차단한다.

부분 수정 스키마에 arc가 포함되어도 같은 전송 변환을 적용한다. arc가 없는 회차/검수 스키마는 변경하지 않는다. 호출 횟수·모델·출력 토큰·비용 정책은 그대로다. 기존 normalize_arc는 배열도 지원한다.

실제 운영 NB-S에 변환을 적용하여 객체 정의 15→8, 속성 정의 95→40, 배열 정의 22→11을 확인했다. 이는 JSON 구조의 감소이며 공급자 내부 grammar 크기나 API 성공을 증명하지 않는다.

실제 오류 문구를 schema_compiled_grammar_size로 분류하는 회귀 테스트도 추가했다.

## 검증 및 운영 재개
- 로컬 P76 309개 통과. 변경 런타임/신규 테스트 Ruff 통과.
- 실제 정본 스키마로 로컬 변환 적용 확인. 정본 프롬프트/스키마 원문은 저장소에 복사하지 않음.
- 유료 API 호출 없음. 공급자 컴파일 수락과 생성 품질은 실제 shadow에서 확인해야 함.
- 현재 N1-BIBLE은 시도3 및 :hold. 코드 배포만으로 재개되지 않는다. 배포 후 명시적인 시도 초기화/보류 해제가 필요하며, 기존 실패 증거와 비용2.3584는 보존한다.
- main 새 shadow 실행에서 변경된 설정 지문, API 응답, B01 및 안전 검수, 비용을 확인한다. 기존 실패 실행 재실행은 이전 커밋을 사용하므로 사용하지 않는다.
- 다시 grammar 크기 초과이면 보류 유지 후 바이블 생성 단계 분리를 검토한다. 배열화만으로 장애 종결하지 않는다.

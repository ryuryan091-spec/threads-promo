# P76 Sonnet 전환·3회 생성·품질 경고 발행 상세설계

## 승인된 요구사항
- Opus 사용 중단. 저장소의 Sonnet 5 계열 식별자 claude-sonnet-5-5로 작성·검수 통일.
- 최초 생성 포함 최대 3회. 실행 내부 2회 반복 제거, 실행별 1회 생성/수정. SDK 자동 재시도 0.
- 3회째 남은 형식·문체 품질 경고만 텔레그램 알림 성공 후 기존 발행 일정으로 진행.
- API 실패, 잘린 출력, 빈/불완전 원고, 개인정보·유해내용 등 안전 검사 실패는 발행하지 않음.
- 기존 live/shadow/dry_run 모드와 발행일·발행 예고 2시간·중복 발행 방지 유지.

## 모델·사용량 제어
- 작성·검수 Sonnet 고정, 요청 모델 허용목록 검사. 서버 fallback 제거로 Opus 우회 호출 방지.
- 동일 모델 중복 AI 검수 제거. 생성 3회 제한은 작성/수정 횟수이며 별도 안전 검수는 필요 시 1회 호출한다.
- 작성 effort=medium, max_tokens=16000 (기존 32000). 실제 Sonnet 품질·토큰 사용량은 운영 관찰 필요.
- 비용 사전 추정은 출력 상한 기준. 월 및 실행 예산 가드 유지.
- 공개 로그: 키/단계/시도/입력/출력/thinking/비용. 원고·프롬프트·키 미출력.
- DB-12 페이지 사용량 JSON에 누적 호출 수·입력/출력·캐시 토큰·비용 기록.
- thinking 토큰이 응답에 없으면 0으로 추정하지 않고 unknown 호출 수를 기록.

## 수정용 초안과 부분 수정
- 완전한 JSON 응답을 수정용 초안 섹션에 보관. 잘린 응답은 보관/발행하지 않음.
- B01은 arc, B02는 cast, B03은 source/arc, 공개문구는 해당 필드, 본문 오류는 body/continuity/summary를 수정 대상으로 선택.
- 정본 스키마에 정의된 필드만 요청하는 투영 스키마를 생성. 지정 외 필드 또는 필드 누락은 거절.
- 수정 결과를 기존 초안과 병합하고 결정론 검사 및 AI 검수를 다시 수행.
- 필드 스키마가 불충분하면 부분 수정은 강제하지 않고 기존 초안+오류를 제공한 전체 응답 방식으로 처리. 이것도 생성 3회 상한 적용.
- 반복 섹션 읽기는 최신 기록을 선택하도록 수정해 과거 초안·사용량을 다시 읽는 문제 방지.

## 3회째 품질 예외 정책
허용목록: R09:cliche, R09:repeated_sentences, Q:too_long, R01:length.
추가 조건: 본문 2000~6000자, 완전한 응답, AI 검수 PASS, 요청 모델 일치, 생성 횟수=3.
알 수 없는 규칙, B01/B02 구조 미완성, 법률·인용·개인정보·유해내용 규칙 등은 예외 불가.
바이블은 게시물이 아니므로 품질 예외 발행을 적용하지 않는다.

완성 원고를 저장하고 품질 경고와 본문/질문/표지/부제 해시를 기록한다.
T7 알림에 3/3회 종료·경고 코드·원고 노션 링크·기존 일정 발행·중단 방법을 전송한다.
전송 성공 시 해시·모드·전송 성공 기록을 저장한다. 실패 시 발행 대상 제외; 다음 생성/게시 점검에서 알림만 재시도한다.
모드가 shadow에서 live로 바뀌면 live 품질 알림을 다시 보내야 한다.
게시 시 내용 해시 불일치면 보류. 기존 개인정보·법률 및 공개 문구 검사는 유지한다.

## 실패·복구
- 핵심 API 예외는 실패 상태로 기록하여 Actions에서 오류를 식별할 수 있다.
- 각 실패 알림에 현재 시도 횟수 포함; 3회 도달 시 자동 생성 종료를 명시한다.
- 기존 3회 소진 행의 카운터를 자동 초기화하지 않는다. 이미 소진한 N1-BIBLE은 검토 후 별도 복구해야 한다.
- 실제 API/Telegram/Facebook을 호출하는 테스트는 수행하지 않았다. 테스트 외부 호출은 합성 응답이다.
